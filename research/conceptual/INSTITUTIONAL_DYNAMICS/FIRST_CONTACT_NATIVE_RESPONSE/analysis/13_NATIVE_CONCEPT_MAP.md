# 13 — Native Concept Map

**Purpose:** reconstruct the conceptual machinery the response itself uses before comparing it with Uruk's framework.  
**Rule:** preserve Wonder Gather's vocabulary where possible. Do not treat this as an ontology.

## 1. Evidence-status vocabulary

The response begins by explicitly separating:

- **Canonical/current**
- **Implemented**
- **Historical**
- **Informal convention**
- **Inference**
- **Open**
- **Working-memory context**

This is not decorative front matter. The rest of the handoff repeatedly uses these categories to prevent project state, design authority, implementation reality, historical provenance, and conversational memory from collapsing into one kind of truth.

## 2. Distributed truth surfaces

Wonder Gather does not present one master artifact as containing all truth.

It assigns different questions to different surfaces:

- `CURRENT_STATE.md` -> present milestone/lifecycle routing;
- `GAME_VISION.md` -> durable design authority under the Game Director;
- `DESIGN_RATIONALE.md` -> dangerous-to-lose reasons;
- `PROJECT_CULTURE.md` -> mnemonic/operational collaboration shorthand;
- code -> implementation truth;
- `UnityProjectContext.md` -> technical continuity/history;
- `Validation.md` -> execution evidence and failure history;
- playtest documents -> human acceptance questions;
- tests -> executable invariants;
- Git -> provenance;
- conversation/high-context memory -> rationale, discarded alternatives, taste, and relationship among decisions.

A central native discipline is therefore **question-to-source routing**.

## 3. Implemented is not Locked

This is one of the response's most repeated distinctions.

Implementation establishes existence, not permanent design authority.

The handoff repeatedly warns that:

- current performance percentages are scaffolds;
- supplies is not the final economy;
- the current creator is not final UI;
- Living Body is not final physical authority;
- current worker lineage is not the final unit architecture.

The project actively protects open design from being silently frozen by code.

## 4. Multiple evidence modes

The response distinguishes technical correctness from lived/experiential acceptance.

It repeatedly uses:

- automated tests;
- stronger invariants;
- rendered/visual probes;
- runtime behavior;
- human playtest.

The Living Body is the clearest native example: compile, geometric invariant, screenshot, and human feel can each reveal different failure classes.

The Game Director's experiential judgment is not described as an inferior substitute for technical evidence. It answers a different question.

## 5. Failure as scar tissue

Section 8 is organized around concrete failures and what changed afterward.

The native process theory is strongly empirical:

- continuity machinery arose from lost context;
- stronger invariants arose from hidden failure;
- visual probes arose because logic tests missed presentation defects;
- defensive persistence arose because player-authored civilizations are high-value state;
- the new continuity layer arose because a high-context AI became a coordination bottleneck.

The handoff consistently describes stronger process as **scar tissue**, not as prior abstract governance design.

## 6. Reversibility and consequence

The response maps work into:

- cheap and reversible;
- expensive but reversible;
- difficult to reverse;
- potentially project-corrupting.

It then scales process accordingly.

This consequence hierarchy is one of the project's strongest native organizing principles:

- low-risk tuning -> lightweight iteration;
- moderate work -> focused tests, regression, human inspection;
- hard-to-reverse semantics -> explicit design reconciliation and stronger evidence;
- silent/project-corrupting change -> isolation and possibly fresh independent review.

## 7. Role vocabulary without role mystification

The current shorthand names:

- **Keeper of the Horizon** — Game Director;
- **Threadkeeper** — high-context design/continuity AI;
- **Worldsmith** — implementation AI/developer;
- **Guest Cartographer** — optional fresh reviewer for rare high-risk work.

But the response repeatedly limits the metaphor:

- the Keeper title is optional; authority is not;
- Threadkeeper is mnemonic, not authority;
- Guest Cartographer is optional, not standing bureaucracy;
- if metaphor creates confusion, discard it.

The native role system therefore treats culture as a **memory/routing aid**, not an independent layer of command.

## 8. Durable state versus high-context integration

The response's clearest memory architecture is:

> durable/retrievable state belongs in artifacts; high-context intelligence should spend attention on integration and meaning.

The repository is described as durable shared memory.

The Threadkeeper should not be the filesystem.

There is no live shared multi-agent memory fabric. Context transfer occurs through artifacts, tests, the human owner, and handoffs.

## 9. Creative integration as the scarce resource

The handoff says the main bottleneck is not coding capacity.

The scarce question is:

> Does this technically plausible thing still belong to Wonder Gather?

That judgment currently belongs to the Game Director.

The response treats implementation as comparatively cheap and integration as increasingly expensive as systems interact.

## 10. Human creative authority is intentionally preserved

The response does not frame Game Director dependence as a defect to automate away.

It explicitly preserves human authority over:

- feel;
- tone;
- aesthetic belonging;
- locking open design;
- milestone experiential acceptance.

If the Game Director disappears, the response describes the continuity loss as more severe than loss of an implementation AI or even the Threadkeeper.

## 11. Technical continuity and semantic continuity are different

The repository can increasingly reconstruct:

- code state;
- milestone state;
- save format;
- tests;
- architecture;
- locked design pillars;
- historical milestone sequence.

Harder-to-reconstruct material includes:

- intensity of preferences;
- discarded alternatives;
- subtle meanings of aesthetic vocabulary;
- why technically valid compromises felt wrong;
- unwritten current judgment.

The response therefore distinguishes **recoverable project state** from **harder-to-recover project meaning**.

## 12. Open questions are protected state

Section 14 explicitly labels unresolved tensions and says not to resolve them in a harness.

The project treats some uncertainty as legitimate and valuable:

- freeform design vs multiplayer balance;
- fictional customization vs numeric control;
- physical emergence vs RTS responsiveness;
- autonomy vs player agency;
- individual variation vs predictability;
- grandeur vs intimacy;
- Open Workshop freedom vs exploitability;
- player-authored progression vs standardized balance;
- current worker lineage vs generic architecture;
- NavMesh-root embodiment vs future physical authority.

Not knowing yet is part of the current truth.

## 13. The project's experiential center

The handoff repeatedly returns to:

- authored civilizations;
- embodiment;
- observation as play;
- grounded/readable/poetic/quietly wondrous tone;
- grand systems and small lives visible together;
- meaningful fictional authorship rather than naked sliders;
- simple commands plus rich readable interpretation.

This experiential center is what technical work is ultimately judged against.

## 14. Native conceptual compression

Across the document, the response's own high-level pattern can be stated without importing Uruk's terminology:

**preserve open design, externalize retrievable state, use several evidence modes, keep human creative judgment where it is genuinely irreplaceable, and increase ceremony only when consequences become silent or hard to reverse.**

This is a reconstruction of the response's native working logic, not a claim that Wonder Gather has declared a formal philosophy.
