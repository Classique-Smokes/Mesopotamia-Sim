# Director Review Guide — Institutional Dynamics Draft

**Status:** DRAFT / NON-AUTHORITATIVE  
**Purpose:** Make review/approval boundaries explicit while the institutional-dynamics package is still conceptual.

## 1. What is currently being reviewed

The draft package proposes:

1. an umbrella future problem — institutional identity, persistence, recognition, authority, capability, memory, and genealogy;
2. a set of distinctions that should probably remain separable;
3. candidate mechanism families that could express those distinctions;
4. Uruk-derived challenge cases for falsifying future designs;
5. a map from SFL v0 into those future questions;
6. a proposed research/design/promotion procedure;
7. several possible post-v0 paths.

None is current simulation authority.

## 2. Possible review outcomes

### A. Preserve as useful conceptual planning

Meaning:

- the package is worth keeping as a working frame;
- future architects/researchers may consult it;
- no mechanism becomes accepted;
- no roadmap changes.

This is the lowest-consequence outcome.

### B. Endorse the umbrella problem / project character

Meaning:

- the project should deliberately preserve room for institutional identity/persistence/recognition as a major long-horizon concern;
- future designs should not casually collapse the key dimensions identified here;
- still no specific mechanism is accepted.

If intended as a durable project-level principle rather than merely planning guidance, this may require explicit constitutional/architectural promotion rather than leaving it in conceptual research.

### C. Approve selected design constraints

Examples:

- historical continuity must remain distinct from current composition;
- authority/capability/recognition must not collapse into one scalar;
- higher-order action must remain reconstructably grounded;
- causal genealogy must remain distinct from official/remembered genealogy.

These would be consequential design/semantic constraints and should be promoted through an explicit decision record if accepted as binding.

### D. Approve specific mechanism families

Examples:

- persistent office object separate from holder;
- artifact transformation provenance;
- typed participation arrangements;
- authority claims with scope/basis;
- task/responsibility objects.

These should **not** be accepted directly from this conceptual draft. They require the research/design procedure in `04_RESEARCH_DESIGN_PROMOTION_PROCEDURE.md`, including existing-substrate audit, bounded historical research where relevant, technical alternatives, challenge-case testing, and an explicit decision.

### E. Select a post-v0 path

This would be a future roadmap/prioritization choice.

The current draft intentionally does not ask for that decision while IMP-0001/v0 is still proving the substrate.

## 3. Recommended review sequence

When reviewing, consider separately:

1. **Umbrella framing** — is institutional persistence/recognition the right larger problem?
2. **Separability** — are any listed dimensions wrongly split or wrongly combined?
3. **Mechanism hypotheses** — which feel promising, premature, or missing?
4. **Challenge cases** — do they capture the failure modes we care about?
5. **v0 bridge** — are we correctly treating v0 as substrate/reference rather than universal institution theory?
6. **Procedure** — is the proposed route from concept → evidence → design → authority appropriately disciplined?
7. **Possible paths** — are there obvious future routes missing, without choosing one now?

## 4. Default interpretation of informal approval

Because conversation is non-authoritative:

- “this looks right,” “good direction,” or similar language should be treated as feedback;
- an explicit request to preserve/update the conceptual package authorizes non-authoritative documentation work;
- a binding project principle, architectural constraint, semantic rule, or roadmap choice requires explicit promotion at the appropriate authority level.

## 5. Current recommendation

While SFL v0 is in implementation:

- preserve this package as a draft future-planning frame;
- let v0 results test the assumed substrate;
- do not select universal institutional mechanics;
- do not change the current slice roadmap;
- revisit promotion only when the Director has reviewed the conceptual distinctions and/or v0 provides concrete evidence about which mechanisms actually generalize.
