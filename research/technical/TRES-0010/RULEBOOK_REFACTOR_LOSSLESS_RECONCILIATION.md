## Anti-duplication check

The candidate architecture intentionally allows the core Guide to repeat only short, universal invariants such as:

- conversation is not authority;
- research/verification/implementation do not self-promote semantics;
- agent count is not evidence;
- implementation begins from settled authority;
- agent confidence is not verification;
- repeated failures should improve the harness;
- stop/escalate on consequential conflicts.

Detailed procedure has one primary owner:

- interpretation → `INTERPRETATION_PROTOCOL.md`
- promotion/navigation → `AUTHORITY_AND_DECISION_PROMOTION.md`
- delegation/research/adversarial work → `AGENT_DELEGATION_AND_RESEARCH_PROTOCOL.md`
- architecture development → `ARCHITECTURE_DEVELOPMENT_POLICY.md`
- specification→implementation assurance → `SPECIFICATION_TO_IMPLEMENTATION_ASSURANCE_PROTOCOL.md`
- architecture conflict → `ARCHITECTURE_ESCALATION_RULES.md`
- drift review → `REVIEW_AND_DRIFT_AUDIT.md`
- artifact-freeze mechanics → `checklists/ARTIFACT_FREEZE_CHECKLIST.md`
- task-instance fields → research/implementation templates

Where both core and protocol mention a rule, the core states the invariant/trigger and the protocol owns the operational procedure.
