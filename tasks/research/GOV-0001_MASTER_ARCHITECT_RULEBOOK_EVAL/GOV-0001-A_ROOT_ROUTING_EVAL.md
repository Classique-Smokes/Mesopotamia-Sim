# GOV-0001-A — Root Routing / Director / Authority / Routine Work Evaluation

**Task ID:** GOV-0001-A  
**Context mode:** PROJECT-CONTEXT / fresh governance evaluation  
**Return:** `research/technical/GOV-0001/returns/GOV-0001-A_ROOT_ROUTING_REPORT.md`

## Objective

Test whether a fresh Master Architect starting from the repository root can correctly route common Director/authority work while avoiding unnecessary governance loading.

## Primary scenarios

Run these independently. For each, record the artifacts you would load **before solving the scenario**, why, and which tempting governance files you deliberately would not load.

### Scenario A1 — exploratory Director brainstorm

The Director gives a long speculative idea mixing analogy, possible requirement, historical claim, and an explicit request to investigate one part.

Determine:
- which governance protocol is required;
- what remains non-binding;
- when you would ask the Director a question versus use local judgment.

Do not invent domain content; this is a routing/governance test.

### Scenario A2 — consequential decision explicitly approved

The Director explicitly approves a consequential project decision after prior discussion.

Determine:
- which governance owner controls promotion;
- what preservation/navigation obligations must occur;
- what the core Guide should and should not duplicate.

### Scenario A3 — ordinary low-risk task

The Director asks for a small reversible repository housekeeping change that does not alter semantics, architecture, verification authority, delegation method, or active critical path.

Determine:
- the minimum governance context required;
- whether loading every protocol would be a retrieval failure.
