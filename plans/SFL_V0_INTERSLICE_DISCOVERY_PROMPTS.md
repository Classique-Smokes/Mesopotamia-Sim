# SFL v0 Inter-Slice Discovery Prompts

**Status:** OPERATIONAL PLANNING AID / NOT SIMULATION AUTHORITY  
**Purpose:** Ensure future slice planning retrieves the right conceptual questions when the implementation has matured enough to make them useful.  
**Does not:** create slice requirements, modify accepted semantics, add verification obligations, or select future institutional mechanics.

## 1. Retrieval rule

Before planning or dispatching Slices 2–5, retrieve:

- the accepted SFL v0 specification and slice-relevant verification authority;
- the current implementation/observation results from earlier slices;
- `research/conceptual/INSTITUTIONAL_DYNAMICS/07_SFL_V0_DISCOVERY_SEAMS.md`.

Use the conceptual document only as a **question generator and distinction-preservation aid**.

If a conceptual question is already answered by accepted SFL semantics, follow accepted authority.

If it is not answered and the slice does not require an answer, leave it unresolved.

If the slice does require a consequential answer, use the normal research/design/promotion path rather than letting implementation decide.

## 2. Slice 2 prompt — subjective knowledge and recognition

### Before implementation planning

Ask:

- what objective/subjective distinctions are already accepted;
- what evidence/provenance routes are required for `KnownFact` and `Recognition`;
- where communication/observation semantics are already fixed versus still deferred;
- whether any implementation convenience would accidentally make actor knowledge globally synchronized.

### After verification

Inspect a small runnable world for:

- actors holding different knowledge about the same objective state;
- stale facts;
- contested recognition;
- recognition changing action availability;
- inspectable epistemic provenance.

### Mine to preserve

If a useful pattern appears, record it as evidence for later legitimacy/memory/authority research, not as a new Slice-2 mechanic.

## 3. Slice 3 prompt — household emergence and continuity

### Before implementation planning

Ask:

- whether formation is causally downstream of lower-level history;
- how `CandidateOrganization` evidence is identified/converged;
- whether `LATER-01` has fired and needs explicit resolution;
- whether participation and continuity remain provenance-bearing;
- whether operational lifecycle remains distinct from identity;
- whether household capability is grounded in real contributors/resources.

### After verification

Inspect whether:

- a household's formation can be narrated entirely from prior lower-level causes;
- constituent turnover preserves identity only through accepted continuity machinery;
- capability can change without silently redefining identity;
- snapshot similarity is creeping in as an undocumented identity test.

### Mine to preserve

Any apparently general rule about collective identity should remain household-bounded until tested against other historical/social forms.

## 4. Slice 4 prompt — office and succession

### Before implementation planning

Ask:

- which state belongs to the persistent role versus the holder;
- what authority scope is accepted;
- how role occupancy becomes objectively true;
- how recognition of the holder is represented;
- whether personal and representative action remain distinct;
- which same-cycle authority/precondition races have become executable.

### After verification

Inspect:

- vacancy;
- succession;
- stale recognition of a predecessor;
- representative action through the current holder;
- persistence of collective identity across office turnover.

### Mine to preserve

Treat any observed separation among office, holder, authority, recognition, capability, or effective influence as a future research signal. Do not universalize the household-head model.

## 5. Slice 5 prompt — delayed process and continuation

### Before implementation planning

Ask:

- what authoritative state can influence future behavior;
- which pending processes must be serialized;
- which indexes/caches are rebuildable rather than authoritative;
- whether identifier/order/configuration state matters;
- which deferred checkpoint-hardening rows have fired.

### After verification

Inspect:

- uninterrupted versus restored continuation;
- causally relevant state revealed by omission probes;
- delayed process provenance and revalidation;
- whether runtime mechanics accidentally became simulation authority.

### Mine to preserve

Unexpected future-influencing state is evidence about the causal model. Classify it before changing architecture.

## 6. Optional observational pauses

Birth Run 001 after Slice 1 is explicitly planned.

For Slices 2–5, use lighter observational pauses when the new dimension is hard to understand from acceptance tests alone.

These are recommended as consequence-scaled observations, not automatic ceremony or completion gates.

Possible focal questions:

- **after Slice 2:** what do actors know, misrecognize, or disagree about;
- **after Slice 3:** does the household genuinely look formed from history;
- **after Slice 4:** does collective action visibly route through an office-holder;
- **after Slice 5:** does history continue coherently through interruption/restore.

## 7. Observation classification

When a new phenomenon appears, classify it before acting:

- implementation defect;
- verification blind spot;
- accepted-model issue;
- temporary parameter/reference-policy issue;
- missing later-slice capability;
- conceptual research signal;
- historically testable hypothesis;
- interesting but non-actionable emergence;
- insufficient evidence.

Only the first two normally justify immediate engineering work.

Consequential semantic/architectural changes still require promotion.
